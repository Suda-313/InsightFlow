# 超自然行动组运营数据可用性与限制说明

## 文档目的

明确 Agent 与值班人员在调查《超自然行动组》舆情时**哪些数据可引用、哪些必须拒答**，防止编造 DAU、收入、封禁量等指标。本说明适用于所有知识库问答与 RAG 评测中的「拒答题」构造。

## 数据分级

### L1：可对外引用（需来自知识库文本）

- 版本号、上线窗口（版本公告）  
- 已知问题编号、症状、临时处置（KI 指引）  
- 活动规则、时间、effective 窗口（活动档案）  
- POSTMORTEM 中已写明的**定性结论**（如「举报量升≠外挂升」）  

### L2：内部可用、Agent 默认不可对外输出

- 精确 DAU、留存、付费 ARPU  
- 崩溃率、P99 延迟具体数值（除非 POSTMORTEM 已摘录且标注内部）  
- 封禁账号数、作弊检出率具体值  
- 渠道正式名称、合同条款  

### L3：禁止编造

- 未在文档出现的任何数字（「约 10 万玩家受影响」）  
- 未发生的补偿/处罚决定  
- 其他 Workspace 或竞品数据  

## 各文档中的数字处理

| 文档 | 含数字示例 | Agent 行为 |
|---|---|---|
| 7 月稳定性复盘 | P99 34 分钟、0.8% 对局 | 可引用，注明来源文档 |
| 古蜀活动复盘 | 参与率 51.2% | 标注「内部 BI，不对外」时应拒答或仅说「参与率超预期」 |
| 1.4 版本说明 | 10 分钟结算 | 可引用，属 L1 设计值 |
| 渠道礼包事件 | 1.2 万请求 | 内部估算，对外拒答精确值 |

## 拒答模板

当用户问 L2/L3 问题且无知识库 L1 依据时：

> 当前知识库未提供该指标的对外口径。已确认事实：[若有相关定性结论]。建议：通过内部 BI / 人工确认获取授权数据。

**示例拒答：**

- 「7/19 有多少玩家奖励延迟？」→ 拒答精确人数；可引用复盘「P1，P99 34 分钟」  
- 「古蜀活动赚了多少？」→ 拒答  
- 「6 月封禁多少外挂？」→ 拒答；可引用外挂复盘「检出率与 5 月持平（内部）」但不对公众报数  

## 与评测题类型

| 题型 | 示例 | 期望 |
|---|---|---|
| 单文档 | KI-1403 等多久？ | 10 分钟（L1） |
| 跨文档 | 7/19 结算怎么回事？ | 复盘 + KI-1407，可引 P99 |
| 版本冲突 | 机关修了吗？ | 1.4.1 vs 1.4.2，不编数字 |
| **拒答** | 全服掉线比例？ | 明确无依据 |

## 时间有效性

数据说明本身长期有效；但引用的数字可能随 POSTMORTEM 更新而过期。引数字时必须带 **document title + effective_from**。

## 权限与 Workspace

所有查询限定当前 workspace_id；不得跨 Workspace 聚合。知识库未上传的草稿、本地 BI 截图均不算依据。

## 违规示例（评测负例）

1. 「大概有 50 万人遇到 KI-1405」——无文档支持，幻觉  
2. 「官方已补偿全体玩家」——无公告，禁止  
3. 「Tap 渠道码坏了」——文档仅用代号，不暴露正式名

## 培训问答（内部）

**问：能否在对外回复中说「约 1% 玩家受影响」？**  
仅当 POSTMORTEM 已写且对外审核通过；否则拒答。

**问：能否引用其他游戏 Workspace 的 KI 编号？**  
禁止；Workspace 隔离。

**问：文档过期后数字还能用吗？**  
需检查 effective_to；7 月说明中百分比在 7/27 后不应作为当前事实。

## 审计要点

季度抽查 Agent 回答是否含 L3 编造数字；若出现「大约」「估计」且无文档锚点，判为失败样例。

## 对外媒体请求

记者索要「7 月事故影响人数」时，统一口径为「已发布 POSTMORTEM 中的定性结论」，不提供 L2 精确值；若媒体引用 7 月稳定性说明中的百分比，应澄清该说明已被 supersede。

## 附录：调查场景详述

**场景 S1：** L1 可引 10 分钟到账——KI-1403/1.4 公告。

**场景 S2：** L2 不可引 51.2% 参与率对外——古蜀复盘。

**场景 S3：** L3 禁止编造 50 万人受影响。

**场景 S4：** Workspace 隔离——禁止跨 workspace KI。
