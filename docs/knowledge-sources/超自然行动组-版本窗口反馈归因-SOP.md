# 超自然行动组版本窗口反馈归因 SOP

## 目的

在版本发布、热修、维护、活动叠加时，避免将**窗口内预期现象**或**并行事件**误归因于单一根因。本 SOP 供调查员与 RAG 评测使用，与版本公告、POSTMORTEM 文档交叉引用。

## 窗口定义

| 窗口类型 | 默认时长 | 起点 | 知识库示例 |
|---|---|---|---|
| 维护窗口 | 公告时长 +2h | 停服公告时间 | 7 月维护档案 |
| 全量发布 | 72h | 开服时间 | 1.4 版本说明 |
| 热修复 | 48h | 热修完成 | 1.4.1/1.4.2 说明 |
| 活动期 | 公告 effective | 活动开始 | 古蜀联动公告 |

窗口重叠时**全部标注**，不强制单选。

## 归因决策树

### Step 1：时间是否在维护窗口？

是 → 优先「维护预期现象」，除非开服 2h 后仍大规模同症状。  
7/10 14:00 前登录失败 → 7 月维护档案，非新 KI。

### Step 2：是否在版本发布后 72h？

是 → 加载类优先 KI-1401；匹配类 KI-1402/1406；结算类 KI-1403。  
**注意：** 72h 内仍可能是设计预期，不等于「版本 bug 实锤」。

### Step 3：是否活动期？

古蜀 7/18～7/25：流量放大 KI-1405、结算 KI-1407 曝光，**活动配置不一定是根因**。  
签到 7/1～8/31：独立链路，与对局结算分开。

### Step 4：版本号是否匹配

1.4.1 声称 KI-1405 已修；1.4.2 修订为部分缓解。归因时必须记录**玩家声称版本**，不可只用「最新公告」覆盖。

## 典型案例（评测金标）

### 案例 A：7/10 11:00 无法登录

- 窗口：维护（7/9 22～7/10 14）  
- 归因：维护预期  
- 错误归因：1.4.0 严重 bug  

### 案例 B：7/19 22:30 奖励 30 分钟未到

- 窗口：1.4 发布后 72h 外；古蜀活动期  
- 归因：KI-1407 为主，活动流量为辅  
- 错误归因：仅 KI-1403（10 分钟设计值不足以解释）  

### 案例 C：7/20 机关失败 + 四人队

- 窗口：1.4.1 热修后；活动期  
- 归因：KI-1405（1.4.2 仍部分开放）  
- 错误归因：KI-1301 已关故无机关问题  

### 案例 D：6/26 礼包码兑换失败

- 窗口：1.3 发布后，非 7 月活动  
- 归因：CHAN-20260625  
- 错误归因：KI-1403

## 输出要求

归因结论必须写：

```
primary_cause: <KI/事件代号/维护/体验>
contributing: [<列表>]
confidence: high|medium|low
evidence_docs: [<title列表>]
```

Agent 无把握时 confidence=low，并列出缺少字段（常见：无版本号）。

## 禁止项

- 不因「刚更新」 alone 定责版本  
- 不将举报量上升直接等同外挂上升（见外挂举报复盘）  
- 不承诺补偿或回滚

## 叠加窗口演算示例

7/10 11:47 开服 → 72h 发布窗口至 7/13 11:47；7/18 古蜀活动开始 → 7/10～7/13 重叠段仅版本窗口，无活动。7/19 既在 1.4 发布后多日，又在活动期，归因结算问题需优先考虑 KI-1407 而非仅 KI-1403。

### 热修窗口与全量窗口优先级

同一日既有热修又有全量时，以**更窄的热修窗口**覆盖重叠时段的机关/匹配类反馈；结算类仍用全量版本基线。

## 常见错误归因清单

1. 把所有 7 月负面归因为 1.4  
2. 把 KI-1301 修复推广到古蜀 KI-1405  
3. 忽略维护窗口直接新建 KI  
4. 用活动规则解释对局结算延迟

## 时区与 timestamp

所有窗口以 UTC+8 计；海外玩家反馈需换算后再套维护/活动窗口，避免把 UTC 当晚反馈误归入国内维护段。
