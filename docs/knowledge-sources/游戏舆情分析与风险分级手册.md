# 游戏舆情分析与风险分级手册

## 目的

本手册为组织内游戏 Workspace 提供统一的舆情分析方法。它用于解释如何识别问题、评估风险和形成建议，不直接替代各游戏的版本公告、已知问题或客服 SOP。

## 主题识别

每条反馈优先按玩家实际受阻点归类：登录/网络、稳定性、匹配/组队、结算/道具、支付、作弊/举报、内容建议或其他。一个反馈可有主主题和次主题，但不要为了提高覆盖率强行归入多个主题。

主题名称必须稳定可追溯。新增主题前先确认现有主题无法表达该问题，避免“卡顿”“闪退”“加载慢”被拆成无法比较的多种名称。

## 风险判断

风险判断至少同时检查四项：

1. 量：反馈量相对近期基线是否异常。
2. 一致性：样本是否描述相同症状、版本和时间窗口。
3. 影响：是否阻断登录、匹配、支付、结算等核心路径。
4. 时效：是否集中发生在版本发布、活动开始或服务变更附近。

单个维度异常不等于事故。只有量、样本和业务影响相互支持时，才可以升级为高风险事件。

## 告警复核流程

1. 先确认数据范围、时间窗口和主题归类是否正确。
2. 抽取最小样本核对症状是否一致；不把情绪词当作技术根因。
3. 检索当前 Workspace 的版本说明、已知问题和 SOP，判断是否已有可复用处置。
4. 输出“已知事实、推测、缺少的信息、下一步建议”四部分。
5. 涉及公告、补偿、风控、处罚或渠道沟通时，创建人工确认项，不由 Agent 自动执行。

## 回应与引用规范

对外或对内回答均应区分数据事实与知识依据：数量、趋势和告警必须引用数据侧证据；版本规则、问题状态和处理口径必须引用知识库证据。检索不到已发布依据时，应明确说明缺少依据，而不是补全一个看似合理的答案。

## 复盘指标

每次重要舆情处理至少记录：主题覆盖情况、异常发现时效、升级准确性、回复引用完整性和后续趋势。评测模型或 Prompt 时，额外记录意图/任务路由正确性、RAG 检索召回率、引用正确率、无依据回答率、耗时和 Token；指标必须注明题集与运行批次。
