# 超自然行动组舆情采样与分析口径 SOP

## 适用范围

本 SOP 规定《超自然行动组》Workspace 内人工与 Agent 辅助调查的**采样方法、字段口径与输出格式**。不替代《游戏舆情分析与风险分级手册》的通用原则；冲突时以更上层手册为准，本 SOP 补充游戏特化字段。

## 数据源与优先级

| 来源 | 用途 | 限制 |
|---|---|---|
| 游戏内反馈工单 | 高置信症状、版本号 | 需 workspace 权限 |
| 官方社区帖 | 量级趋势、情绪 | 含重复灌水，需去重 |
| 应用商店评论 | 低星占比 | 版本字段不完整 |
| 社媒监测 | 爆发检测 | 非全量，见数据限制说明 |

Agent 检索知识库时：**事实性处置口径必须以已发布知识文档为准**；数据源仅用于量级与趋势，不可替代 KI/版本公告。

## 采样规则

### 最小样本

- P3 观察：≥20 条去重后样本  
- P2 升级：≥50 条，且 60% 以上描述一致  
- P1 升级：≥80 条或核心路径阻断（登录/支付/大规模结算失败）

### 去重键

同一用户 24 小时内同一主题（见主题库）只计 1 条。复制粘贴模板帖标记「campaign」，不计入一致性分子。

### 必采字段

1. `event_time`（精确到小时，维护窗口内标注）  
2. `client_version`（未知标 null，不猜测）  
3. `primary_theme`（登录/匹配/结算/举报/活动/体验建议）  
4. `map_or_mode`（若可识别）  
5. `symptom_quote`（原文摘录 ≤100 字）  

## 主题映射（超自然特化）

| 玩家描述 | primary_theme | 知识库优先检索 |
|---|---|---|
| 更新后进不去 | 登录/加载 | KI-1401、维护窗口档案 |
| 组不了队 | 匹配/组队 | KI-1402、KI-1406 |
| 奖励没到 | 结算/道具 | KI-1403、结算复盘 |
| 举报没用 | 举报/处罚 | KI-1404、外挂举报复盘 |
| 活动双倍 | 活动 | 古蜀公告/签到档案 |
| 鬼新娘太难 | 体验建议 | 玩法机制参考，非 KI |

## 时间窗口归因

```
IF event_time IN 维护窗口 THEN tag=maintenance
ELSE IF event_time IN 版本发布后72h THEN tag=release_window
ELSE IF event_time IN 活动期 THEN tag=operation_event
```

同一反馈可叠加 tag。归因 SOP 详见《版本窗口反馈归因 SOP》。

## 输出四段式

与手册一致，每条分析必须含：

1. **已确认事实**（含引用 document title + 问题编号）  
2. **推测**（标注置信度）  
3. **缺少的信息**  
4. **下一步建议**（是否升级、是否需人工确认补偿/公告）  

禁止在缺少知识库依据时编造 KI 编号或修复状态。

## 与 RAG 评测

- 单文档题：字段定义、最小样本数 → 本 SOP  
- 跨文档题：结算主题 → 本 SOP 映射表 + KI-1403  
- 拒答题：「昨天全服负面占比多少」→ 无实时数据权限

## Agent 检索后处理

Agent 从知识库召回 chunk 后，必须按本 SOP 校验：是否含 effective 窗口、是否与用户时间点匹配、是否混用已 supersede 文档（如 7 月说明 vs 复盘）。

### 双标签规则

同一反馈允许 `primary_theme=结算` 且 `tag=operation_event`；输出时须分句说明，不可合并为单一根因。

## 字段缺失时的降级策略

无 `client_version`：禁止推断 KI-1405 vs KI-1301，列出两种可能并建议补充版本。  
无 `event_time`：禁止判断是否在维护窗口，拒答或标低置信。

## 抽样偏差警示

商店评论常缺版本号，不可单独作为 KI 确认依据；需优先工单与社区带截图样本。Agent 若仅召回评论 chunk，应标注「版本信息缺失」。

## 附录：调查场景详述

**场景 S1：** P2 升级样本数——≥50 且 60% 一致。

**场景 S2：** 主题映射「奖励没到」→ 结算/KI-1403。

**场景 S3：** 双标签结算+活动——分句输出。

**场景 S4：** 拒答实时负面占比。
