# 超自然行动组玩家反馈响应 SOP

## 目标与边界

本 SOP 用于把评论、客服反馈和舆情线索转成可复核的处理动作。它不替代技术故障判定，也不允许客服或 Agent 承诺补偿、处罚或修复时间。

## 第一步：分流与记录

收到反馈后，先记录发生时间、客户端版本、反馈渠道、问题关键词和是否影响核心流程。根据内容分为：稳定性、登录/网络、匹配/组队、结算/道具、作弊/举报、建议或其他。

不要收集密码、验证码、完整账号信息或无关个人信息。评论中包含联系方式时，只保留脱敏后的处理摘要。

## 第二步：风险分级

| 等级 | 判断条件 | 首次动作 | 时限 |
|---|---|---|---|
| P0 | 大面积无法登录、支付或数据安全风险 | 立即升级值班负责人 | 15 分钟内确认受理 |
| P1 | 核心玩法受影响且同类反馈持续增加 | 建立问题单，关联已知问题 | 1 小时内复核 |
| P2 | 存在稳定复现路径但影响有限 | 收集最小复现信息 | 当日处理 |
| P3 | 建议、体验表达或单一低置信度反馈 | 归档并进入主题观察 | 周期复盘 |

评论数量增加不是自动升级条件。升级必须同时参考样本一致性、影响范围、时间集中度和已有问题状态。

## 第三步：对外回复口径

1. 已知问题：说明已确认的症状和可执行临时操作，引用对应问题编号。
2. 未确认问题：说明正在核对，邀请补充最小必要信息；不得把猜测当成原因。
3. 奖励或道具：先区分显示延迟和实际缺失；超过既定观察时间后再升级人工核查。
4. 举报与外挂：确认已受理，不披露他人处罚细节，不承诺即时处理结果。
5. 负面情绪：先回应玩家实际受阻点，再说明下一步；避免模板化道歉覆盖事实。

## 第四步：闭环与复盘

每个 P0/P1 事件需要记录发现时间、证据来源、影响判断、采取动作、后续指标和关闭理由。复盘重点是“哪些证据支持该判断”和“哪些信息仍缺失”，而不是单纯罗列评论数量。

当 Agent 回答玩家反馈处理建议时，只能给出建议和升级路径；任何补偿、公告发布或策略调整都必须由人工确认。
