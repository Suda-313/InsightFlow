# CSV 导入可靠性修复设计

## 目标

在不增加消息队列、独立 Worker 服务或新基础设施的前提下，让 CSV 导入具备映射可追溯、并发幂等、任务可恢复和稳定 API 错误契约。

## 已确认边界

- 保持 Spring Boot 模块化单体和 PostgreSQL + MinIO 的既有技术边界。
- 不引入 Redis 队列、Kafka、独立任务服务或多 Agent。
- 原始 CSV 继续仅保存在 MinIO；PostgreSQL 只保存映射快照、脱敏反馈和安全错误摘要。
- 不新增单元测试；实施完成后只运行现有测试和本地 CSV 回归。
- 不重写已执行的 Flyway V2--V4 迁移；新增迁移承载本次字段与索引变化。

## 根因

当前 `start` 在事务提交后直接调用内存中的 `@Async` 方法。进程在任务创建后崩溃，或运行中的线程异常退出时，数据库没有可再次领取的机制，任务会长期停在 `queued` 或 `running`。

任务只保存文件 UUID，Worker 执行时再读取 `import_file.mapping_json`。因此文件已经开始导入后仍能修改映射，重跑或延迟执行会使用不同的输入。

幂等键和行去重均采用“先查询、后插入”。并发请求可以同时通过查询，在唯一约束处才发生冲突；Worker 若没有把这个冲突转换为受控结果，任务状态无法可靠收敛。CSV 预览和 Worker 分别解析表头，重复表头会覆盖前一个列索引。

## 方案

### 1. 映射快照与文件状态

创建任务时把已经验证的 `ImportMapping` 序列化进 `async_task.payload_json`，与文件 UUID 一起成为不可变任务输入。Worker 只读取任务快照，不再读取可变的 `import_file.mapping_json`。

文件只允许在 `uploaded` 或 `mapped` 状态保存映射。开始任务时在同一数据库事务中锁定文件、验证 `mapped` 状态，并把文件置为 `processing`；最终由任务执行结果置为 `processed` 或 `failed`。因此导入期间的映射修改会以 422 被拒绝。

### 2. 数据库任务领取与恢复

新增 `lease_owner`、`lease_expires_at`、`started_at` 和 `finished_at` 字段，并增加按 `status/lease_expires_at` 查询的索引。应用内 `@Scheduled` 调度器以固定间隔查找 `queued` 或租约过期的 `running` 任务。

领取操作在一个短事务中完成：用 PostgreSQL `FOR UPDATE SKIP LOCKED` 锁定一条候选任务，检查尝试次数，再写入 `running`、租约和尝试次数。实际 CSV 解析在锁之外执行；结束时另开短事务按任务 UUID 和租约所有者收敛为成功、部分失败或失败。应用启动后第一次扫描同样会恢复未完成任务。

任务达到最大尝试次数时，调度器将其置为 `failed` 并给文件写入失败状态。这样不会无限重试，也不会把重启前的运行任务遗忘。

### 3. 幂等与反馈去重

`start` 先锁定文件，再查询同一 workspace、任务类型和幂等键。新建任务若碰到数据库唯一约束冲突，会重新读取既有任务：输入一致则返回它，输入不一致则返回验证错误。对于同一文件的第二次启动请求，返回进行中的或已完成任务，而不是新建第二个导入任务。

写入反馈事件时保留数据库唯一约束作为最终边界。Worker 将唯一约束冲突识别为 `duplicate`，而不是让整个任务回滚；其他数据库错误收敛为任务级失败并释放租约。

### 4. 统一 CSV 解析规则

抽取共享 CSV 格式和表头校验器。预览和 Worker 在去 BOM、trim 后都校验：表头不能为空且不得重复。重复表头直接返回 `VALIDATION_FAILED`，不允许静默覆盖列索引。

### 5. API 错误契约

异常处理器统一返回：

```json
{
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "请求参数不合法。",
    "trace_id": "...",
    "field_errors": []
  }
}
```

导入 API 的 DTO 使用 snake_case，例如 `created_at`、`file_id` 和 `task_status`。成功响应不泄漏内部主键、对象键、原始 CSV 或真实 PII。

## 非目标

- 不实现任务进度百分比、取消、SSE 或人工重跑接口。
- 不清理或重写已经落库的 V2--V4 迁移历史。
- 不改变 PII 脱敏规则的业务范围。
- 不增加新的自动化测试文件。

## 验收方式

1. 同一映射启动导入后，再保存映射被拒绝。
2. 同一幂等键重复提交返回同一任务；不同文件复用同一幂等键被拒绝。
3. 重复表头在上传预览阶段被拒绝。
4. 数据库中遗留的 `queued` 或过期 `running` 任务能被调度器重新领取，或在超过最大尝试后明确失败。
5. 现有 Maven 测试通过，并用本地 MinIO/PostgreSQL 完成一次 CSV 上传、映射、导入和结果查询回归。
