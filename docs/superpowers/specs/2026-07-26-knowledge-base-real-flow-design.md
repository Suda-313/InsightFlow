# 知识库与真实评论数据闭环设计

## 目标

在“超自然行动组”Workspace 中，以 `output` 目录的 CSV 评论作为舆情事实数据，验证现有 InsightFlow 的导入、分析、受控 Agentic RAG、聊天引用和评测链路。该阶段不新增产品能力；若执行中发现阻断链路的缺陷，只进行与根因直接相关的最小修复。

## 知识库内容与范围

首批发布四份 Markdown 文档：

| 标题 | 类型 | 范围 | 作用 |
|---|---|---|---|
| 超自然行动组 1.4 版本更新说明 | `RELEASE_NOTE` | 当前 Workspace | 回答版本改动、上线时间及影响范围 |
| 超自然行动组已知问题与处置指引 | `KNOWN_ISSUE` | 当前 Workspace | 回答已确认问题、影响与临时处理方式 |
| 超自然行动组玩家反馈响应 SOP | `SUPPORT_SOP` | 当前 Workspace | 回答投诉分流、升级、补偿和闭环流程 |
| 游戏舆情分析与风险分级手册 | `SENTIMENT_PLAYBOOK` | Organization 通用 | 回答评论分类、风险分级、告警与回应原则 |

文档采用完整的游戏运营语境，但不声称来自任何外部官方公告、真实项目组或受授权的内部资料。文档标题和正文不额外附加“测试样例”标识；其目的仅为在项目演示中提供可检索的业务上下文。

## 数据与运行流程

1. 检查 CSV 的编码、字段、时间范围、行数、空值和重复情况，并将字段映射到导入契约：`feedback_text`、`occurred_at`、`source`、`external_ref`，其余可用字段进入 `dimensions`。
2. 创建或确认“超自然行动组”Workspace，上传四份 Markdown 文档，分别按既定范围发布；只有 `PUBLISHED` 版本可进入 RAG。
3. 导入 CSV，核对成功、跳过和失败数量，并等待或触发既有分析流程产出主题、指标和告警。
4. 通过现有聊天 API/前端提问验证两类事实：舆情数据问题应引用指标/告警证据；版本、问题、SOP、舆情方法问题应引用知识库证据。无依据问题应明确说明缺少依据。
5. 执行现有评测能力，记录意图识别准确率、RAG 召回率、引用正确率、无依据断言率以及可取得的耗时/Token 指标。

## 验收标准

- 四份文档均可在知识库列表中看到，并显示为 `PUBLISHED`。
- CSV 导入数量、跳过数量和失败原因可以从运行结果追溯。
- 至少一次 RAG 提问返回对应文档的稳定证据引用；至少一次舆情数据提问返回数据侧证据。
- 评测结果及异常项被记录到项目开发文档，且每个数值说明其运行批次、数据范围或限制。
- 不提交原始评论 CSV、密钥、用户标识或模型原始思维链。

## 非目标

- 不开发爬虫、真实官方数据同步、用户/角色系统或写操作 Agent。
- 不为演示临时增加新的检索类型、向量库或评测框架。
